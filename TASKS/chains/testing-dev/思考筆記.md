### 重要發現
1. **Chinese character handling**: server.js 的 slugify regex `[^a-z0-9\u4e00-\u9fff]` 會**保留**中文字元，不是移除。這是預期行為。

### 發現的 Server Bug：Slug Trailing Hyphen
**檔案**: `server.js` 第 218-221 行
**問題**: `.replace(/-+/g, '-')` 只會折疊連續 hyphen，但不會移除末尾的單個 hyphen。
**觸發條件**: 暱稱末字元為特殊字元（如 `!@#`）
**範例**: `'John Doe!@#'` → `'john-doe---'` → `.replace(/-+/g, '-')` → `'john-doe-'`（末尾殘留 `-`）→ `user-john-doe--{suffix}`
**修復方向**: 在 `.replace(/-+/g, '-')` 後加入 `.replace(/-$/, '')` 移除末尾 hyphen。

### 重要 Bug：provisionAgent 是同步函數，不是 async！

**問題根源**：
- `provisionAgent` 在 `provisioner.js` 中是 `function provisionAgent({...})` — **同步函數**
- 最初使用 `mockResolvedValue({ containerId: ..., containerName: ..., imageName: ... })`
- `mockResolvedValue` 讓 vi.fn() 返回 `Promise.resolve({...})`
- `server.js` 的 activate handler **不 await** `provisionAgent()`，直接 `const result = provisionAgent(...)`
- `result` 變成 Promise 對象，`result.containerName` 為 `undefined`
- 但 catch block 不會被觸發（Promise 不拋錯），最終返回 `{ success: true, status: 'running', containerName: undefined }`
- supertest 的 `expect(res.body).toEqual({ success: true, ... })` 因為 undefined 字段被 JSON 序列化時省略而"部分通過"

**修復**：使用 `mockReturnValue({...})`（同步返回值）而非 `mockResolvedValue({...})`（異步 Promise）。
