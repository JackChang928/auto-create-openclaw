## T7: Refresh Token Rotation — 實作（2026-04-10T00:41:00Z）

### 結果：✅ PASSED

### 實作內容

**目標**：Refresh token 一次性使用（one-time use），每次 refresh 時自動撤銷舊 token 並頒發新 token，防止 replay 攻擊。

**核心修改**：`POST /api/auth/refresh` 端點（原 L261-280）

| 步驟 | 實作 |
|------|------|
| 1. 驗證舊 token | `getRefreshTokenPayload(refresh_token)` — 從 Redis 讀取 payload |
| 2. 撤銷舊 token | `redisClient.del(\`refresh_token:${refresh_token}\`)` — 立即刪除 |
| 3. 頒發新 access_token | `jwt.sign(jwtPayload, JWT_SECRET, { expiresIn: '24h' })` |
| 4. 頒發新 refresh_token | `crypto.randomBytes(32).toString('hex')` — 256-bit random |
| 5. 存儲新 refresh_token | `storeRefreshToken(newRefreshToken, payload, 604800)` — TTL 7天 |
| 6. 回傳新 tokens | `{ success, token, refresh_token, expires_in }` |

**Rotation 特性**：
- 舊 refresh_token 在使用後立即從 Redis 刪除，無法再次使用
- 每次 refresh 頒發全新的 access_token + refresh_token 配對
- 防止盜取的 refresh_token 被重複使用（盜取者與合法用戶同時持有一個 refresh_token 時，先用者成功，後用者失敗）

### 驗證測試

```
Step 1: Login → 取得 refresh_token=A
Step 2: Refresh (refresh_token=A) → 成功
         回應：{ token: B, refresh_token: C }
         ✅ 舊 token A 已從 Redis 刪除
Step 3: Refresh (refresh_token=A) → 401 "Invalid or expired refresh token" ✅
Step 4: Refresh (refresh_token=C) → 成功，產生新 tokens D + E ✅
```

### 攻擊模型覆蓋

| 攻擊場景 | Rotation 保護 |
|---------|--------------|
| 攻擊者盜取 refresh_token | 合法用戶先使用 → 舊 token 撤銷 → 攻擊者無法使用 ✅ |
| 攻擊者中途截持（MITM） | 每次 refresh 換新 token，長期session安全 ✅ |
| 舊 token 重放（Replay）| 一次性使用，Redis DEL 後無效 ✅ |
