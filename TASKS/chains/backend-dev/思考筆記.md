## T8 ✅ 2026-04-09T14:50:00Z
**任務**: `provisioner.js` - `ensureDockerImage()` 邏輯完整性
**驗證方式**: 靜態代碼分析 `provisioner.js`
**結果**: ✅ 通過（有 notes）

**分析**:
- `ensureDockerImage(imageName)` 存在於第 333 行 ✅
- 調用 `dockerImagePresent(imageName)` 檢查鏡像是否已存在 ✅
- 鏡像不存在時執行 `execFileSync('docker', ['pull', imageName], { stdio: 'inherit' })` ✅
- 在 `provisionAgent()` 流程中被調用（第 553 行）✅

**⚠️ Notes（不阻擋通過，但值得關注）**:
1. **同步阻塞**: `execFileSync` 為同步操作，大型鏡像 pull 會阻塞 Node.js 事件循環（建議未來改用 `child_process.spawn` 非同步拉取）
2. **無錯誤處理**: `execFileSync` 沒有包在 try/catch 中，拉取失敗（如網路問題、鏡像名錯誤）會導致整個 process 崩潰
3. **stdio: 'inherit'**: 拉取進度會直接輸出到父進程 stdout，在 daemon 模式下可能不需要這樣的輸出

**判定**: ✅ 邏輯完整，基本功能正確，筆記已記錄未來優化方向

**新增函數**:
```javascript
const SHARED_NETWORK = 'openclaw_shared_net';

function networkExists(networkName) {
  return !!tryRun('docker', ['network', 'inspect', networkName]);
}

function ensureSharedNetwork() {
  if (!networkExists(SHARED_NETWORK)) {
    run('docker', ['network', 'create', SHARED_NETWORK], { timeout: 10_000 });

}
```
