#### 關鍵發現

**✅ 做對的事：**
1. `postgres` 有完整 healthcheck：`pg_isready`，litellm/billing-service 正確使用 `condition: service_healthy` 等待它
2. 所有依賴都聲明了 `condition`（service_healthy 或 service_started）

**⚠️ 風險點：redis 無 healthcheck**
- `auth-service`、`billing-service`、`fluent-bit` 都依賴 redis，但只使用 `condition: service_started`
- `service_started` 只代表容器進程啟動，不等於 redis 完成 INIT/BIND 並可接受連接
- 如果 redis 啟動較慢，依賴它的服務可能嘗試連接失敗
- **建議**：為 redis 添加 `redis-cli ping` healthcheck

**T4 間接通過**：`litellm` 依賴 `postgres: condition: service_healthy` ✅ 已在 docker-compose.yml 正確聲明
**T5 間接通過**：`auth-service` 依賴 `redis: condition: service_started` ✅ 已在 docker-compose.yml 正確聲明

#### 建議改進
```yaml
# redis 建議添加 healthcheck
healthcheck:
  test: ["CMD-SHELL", "redis-cli ping"]
  interval: 5s
  timeout: 3s
  retries: 5
```

同時 `depends_on` 升級為 `condition: service_healthy`：
```yaml
depends_on:
  redis:
    condition: service_healthy  # 改 service_started → service_healthy
```

#### 📋 Section 4 建議填充內容

```bash
wait_for_service() {
  local container=$1; local cmd=$2; local name=$3
  local waited=0
  while ! docker exec "$container" sh -c "$cmd" &>/dev/null; do
    [ $waited -ge 120 ] && fail "$name 未在 120秒內就緒"
    sleep 3; waited=$((waited + 3))
    info "等待 $name... (已等待 ${waited}s)"
  done
  ok "$name 就緒"
}
wait_for_service "openclaw-postgres" "pg_isready -U litellm -d litellm" "Postgres"
wait_for_service "openclaw-redis" "redis-cli ping" "Redis"
```
